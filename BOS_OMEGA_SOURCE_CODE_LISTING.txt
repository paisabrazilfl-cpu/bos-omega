[IN-MEMORY DATA STRUCTURES]

interface Task {
  id: number
  objective: string
  status: "pending" | "running" | "completed" | "failed"
  progress: number (0-100)
  result?: string
  error?: string
  createdAt: Date
  completedAt?: Date
}

interface AuditLog {
  id: number
  timestamp: Date
  level: "INFO" | "WARN" | "ERROR" | "AUDIT"
  event: string
  detail: string
  tool: string
}

[ROUTES]

POST /api/tasks
  - Body: { objective: string }
  - Creates new task, stores in memory
  - Returns: { success: true, task: Task }
  - Broadcasts: taskCreated event

GET /api/tasks
  - Returns: Task[]
  - Sorted by creation date (newest first)

POST /api/tasks/:id/execute
  - Body: { command: string }
  - Executes via: execSync(`/home/ubuntu/bos_omega_prod run "command"`)
  - Updates task status: pending → running → completed/failed
  - Timeout: 30 seconds
  - Broadcasts: taskUpdated event
  - Returns: { success: true, result: string, error?: string }

GET /api/audit-logs
  - Returns: AuditLog[]
  - Sorted by timestamp (newest first)

GET * (catch-all)
  - Serves index.html for client-side routing

[WEBSOCKET IMPLEMENTATION]

Connection Handler:
  1. Add client to Set<WebSocket>
  2. Send initialState (all tasks + logs)
  3. On close: remove from Set

Broadcast Function:
  - Sends JSON message to all connected clients
  - Checks readyState === 1 (OPEN)
  - Used for real-time updates

Message Types:
  - initialState: { type, tasks, logs }
  - taskCreated: { type, task, log }
  - taskUpdated: { type, task, log }

[ERROR HANDLING]

try-catch blocks around:
  - execSync (command execution)
  - File operations
  - Network calls

Error Response:
  - HTTP 500 status
  - JSON error object
  - Audit log entry
  - WebSocket broadcast

9. SECURITY FEATURES
================================================================================

Risk Classification:
  - Detects destructive commands (Remove-Item, rm, delete)
  - Detects financial operations (transfer, payment)
  - Detects external API calls
  - Detects local write operations

Approval Gate:
  - Blocks high-risk operations without --approve flag
  - Escalates to user for manual review
  - Logs all escalations

Audit Trail:
  - Every operation logged with timestamp
  - Includes: event, detail, tool, level
  - Exportable to CSV

Error Isolation:
  - Failures don't affect other tasks
  - Automatic recovery with retry logic
  - Graceful degradation

Resource Limits:
  - Command timeout: 30 seconds
  - Buffer limits: 16KB per response
  - Max retries: 5 attempts
