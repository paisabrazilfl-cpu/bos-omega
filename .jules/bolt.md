## 2024-07-20 - String Normalization vs Multi-pass Case-Insensitive String Scanning
**Learning:** Case-insensitive string searching in C via `strcasestr` is significantly slower than exact matching with `strstr` because it performs character conversion during every comparison, resulting in an O(N*M) scan complexity where each pass converts characters. Pre-normalizing haystacks to lowercase once per scope is a high-impact optimization for multi-match scenarios, reducing scanning to O(N+M) and delivering a ~2.7x speedup under compiler optimization. However, under lower optimization levels or without compiler inlining, stack-allocation overhead of large buffers (e.g. 16KB) can offset minor search wins if iterations are high, meaning pre-normalization works best when compiled with higher optimization levels (-O3) or when the haystack is reused across numerous matching conditions.
**Action:** Use a single, safe stack-allocated lowercase normalization pass followed by exact `strstr` matches to replace multiple case-insensitive search calls in security governance and routing layers. Ensure compiler optimization (-O3) is active or scope haystacks carefully to maximize performance gains.
